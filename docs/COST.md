# Cost

Generated by `make cost` ([surakshit/cost.py](../surakshit/cost.py)) from the assumptions at the top of that file: on-demand list prices as I understood them in October 2026, rounded up, free tier ignored. Check them in the AWS Pricing Calculator for ap-south-1 before quoting; the point is what dominates, not the third digit.

## Idle month (no earthquake): about $12

| Item | USD / month |
|---|---:|
| WAF web ACL + 4 rules (us-east-1) | 9.00 |
| CloudWatch alarms (17 across both regions) | 1.70 |
| SQS: Lambda long-polling 4 empty queues | 1.05 |
| Activator Lambda (every minute, primary only) | 0.08 |
| DynamoDB (activator reads, storage, PITR on ~0 GB) | 0.02 |
| CloudWatch Logs | 0.03 |
| API Gateway, CloudFront, S3, SNS, SSM, custom metrics | 0.05 |
| **Total** | **11.93** |

Three-quarters of the idle bill is WAF. I kept it: the moment you need a WAF is the moment you can't safely deploy one. Without it the idle bill is about $3.

The standby region costs about $1 a month idle (its alarms and its pollers), which is why warm standby beats pilot light here (ADR-005).

## One event: 15 million people, 19.5 million check-ins

| Item | USD |
|---|---:|
| CloudFront requests + transfer | 161 |
| WAF requests | 65 |
| API Gateway (check-ins + uncached reads) | 51 |
| SQS (send, receive, delete) | 9 |
| Lambda (writer, read API, aggregator) | 12 |
| DynamoDB writes, replicated to the standby | 25 |
| DynamoDB reads (uncached lookups) | 2 |
| **Platform total** | **325** |

Assumptions: 1.3 check-ins per person (main shock plus aftershock updates), 4 lookups per check-in, 60% of lookups served from CloudFront's cache.

## SMS is the expensive part

| SMS | Messages | Local aggregator (~$0.01) | International gateway (~$0.10) |
|---|---:|---:|---:|
| With the budget breaker | 3.0 M | $30,500 | $305,000 |
| Without it | 7.0 M | $70,500 | $705,000 |

Assumptions: 10% of people check in by SMS and 70% of them also send a FIND; 20% of web check-ins list family numbers, 1.5 each. The breaker caps *notifications to contacts* at 500,000 per event (a stack parameter) and never caps replies to people who texted us, who have no other channel.

**SMS is 99% of the event's cost, even through a local aggregator.** So the design puts its cost effort there, not in shaving Lambda milliseconds:

1. The free web lookup is the primary way families find out; SMS notification is the extra.
2. Replies go in the sender's language only. A Devanagari message is UCS-2 (70 characters per segment); a bilingual one costs 3-4 segments where one language costs 1-2 (`messages.segments`).
3. Up to 3 contacts per check-in, not unlimited.
4. Per-event budget breaker with an alarm, so a human decides whether to spend more.
5. A local aggregator rather than an international gateway, roughly 10x cheaper per message.

## Cost decisions in the code

| Decision | Effect |
|---|---|
| **API Gateway → SQS with no Lambda in the accept path** | No compute charge (and no concurrency) per accepted check-in |
| **HTTP API, not REST API** | About a third of the per-request price, and the SQS integration is first-class |
| **On-demand DynamoDB, pre-warmed once** | $0 throughput charge while idle; warm throughput is a one-time charge, not a monthly one |
| **Writer batches of 100** | 195,000 Lambda invocations for 19.5 million check-ins |
| **Counters folded per batch, from the stream** | A few counter writes per batch instead of one per check-in, and stream reads by Lambda are free |
| **CloudFront caches lookups 30 s** | Assumed 60% of lookups never reach API Gateway, Lambda or DynamoDB |
| **Custom metrics only when non-zero** | The activator runs every minute; emitting "0 events opened" would bill a custom metric all year. Idle custom-metric cost is $0 |
| **One SMS language per message** | Halves or better the segments per Nepali SMS |
| **SMS budget breaker** | Bounds the only line item that can reach six figures |
| **Notifier MaximumConcurrency 10** | Stays under the aggregator's rate limit instead of paying for throttled retries |
| **arm64 (Graviton) Lambdas** | ~20% cheaper per GB-second |
| **Log retention 14 days; access logs without paths** | CloudWatch keeps logs forever by default; and the shorter log line is also the privacy fix |
